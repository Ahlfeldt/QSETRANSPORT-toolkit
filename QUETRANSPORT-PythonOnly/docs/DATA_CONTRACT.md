# Preliminary standardized data contract

This contract is deliberately strict. Arbitrary spatial dimensionality is supported only when every component refers to the same set of locations.

## Canonical identifier rule

`locations.csv` defines the canonical location set and ordering. Every other file must contain the same unique `location_id` values. Geometry is joined and reordered by identifier; physical shapefile row order is never trusted.

## Required model table: `locations.csv`

Columns:

| Column | Status | Meaning and validation |
|---|---|---|
| `location_id` | required | Unique, non-missing string identifier. |
| `population` | required | Baseline residents; nonnegative and positive in aggregate. |
| `employment_raw` | required | Observed jobs before balancing; nonnegative and positive in aggregate. |
| `employment_model` | generated | `employment_raw × sum(population)/sum(employment_raw)`. |
| `rent_floor_space` | required | One observed baseline floor-space rent in declared units; finite and strictly positive at every retained location. The same observation enters the commercial and residential inversion conditions. |
| `land_area` | required | Developable land area in declared units; strictly positive. |

Additional source columns may be retained for provenance but are not passed implicitly into the model.
### Interpretation of the rent input

QUETRANSPORT currently implements **one observed-rent option**. The input
`rent_floor_space` is a floor-space rent—not land rent—and is not interpreted
as a regulatory wedge. During baseline inversion Python uses this same observed
rent in both the commercial and residential demand equations. This is a
maintained data restriction, not a claim that the two uses have identical
demand.

The counterfactual solver retains separate endogenous bid rents: commercial
`q` and residential `Q`. They are equal in mixed-use locations by the model's
no-arbitrage condition, but may differ at specialized corner locations. The
reported annual land rent is a third object: the developer residual derived
from equilibrium floor-space revenues and the land share.

## Model-consistent wages

Wages are not a user input and are not generated by GRID. During baseline
inversion, the Python model jointly updates total productivity and amenities until the
commuting probabilities reproduce observed workplace and residence employment.
At every iteration workplace wages satisfy the firm's first-order and
zero-profit conditions:

`w_i = alpha × A_i^(1/alpha) × ((1-alpha)/R_i)^{(1-alpha)/alpha}`.

Consequently, the converged wage vector is internally consistent with observed
employment margins, the common baseline floor-space rent, commuting costs, and
the configured structural parameters. No auxiliary employment-wage elasticity
is used.
## Geography

A shapefile or GeoPackage contains exactly one valid geometry for each `location_id`, in a declared coordinate reference system. Because a shapefile consists of several files, all components must be kept together. GeoPackage may be the preferred standardized format while shapefile remains accepted.

## Travel-time matrices

Two labeled square matrices are required:

- `travel_times_baseline.csv`;
- `travel_times_counterfactual.csv`.

Requirements:

- N rows and N columns of travel times plus labels;
- row and column labels exactly match the canonical IDs;
- the same origin–destination orientation in both matrices;
- declared common unit, preferably minutes;
- finite nonnegative entries or a separately declared unreachable-pair convention;
- a documented diagonal/intrazonal convention.

The loader reorders by labels and refuses unlabeled matrices in the general-purpose interface. Dense matrices scale as N²; a future sparse format may be needed for very large grids.

## Optional polygon-level primitive changes

Set `scenario.shocks_shapefile: null` for a pure transport experiment. Python
then removes stale standardized shocks and Python keeps all inverted
fundamentals at their baseline values.

To combine transport with another policy, supply a polygon shapefile or
GeoPackage in arbitrary spatial units. The polygons do not need to match—or
know—the model grid. Source field names are selected in `project_config.yaml`;
the defaults `prod_hat`, `amen_hat`, and `dens_hat` respect the shapefile
10-character field-name limit.

| Standardized column | Default source field | Meaning |
|---|---|---|
| `productivity_hat` | `prod_hat` | Multiplicative change in fundamental productivity $a_i$. |
| `amenity_hat` | `amen_hat` | Multiplicative change in fundamental amenity $b_i$. |
| `structural_density_hat` | `dens_hat` | Multiplicative change in floor-supply fundamental $\varphi_i$. |

Hats are levels relative to baseline: `1.00` means no change, `1.10` means a
10% increase, and `0.90` means a 10% decrease. Set a field mapping to `null`
when that primitive does not change. Supplied fields must be finite and
strictly positive for every source polygon.

### Areal attribution rule

Primitive hats are intensive policy variables. GRID computes exact polygon
intersections in a projected metre CRS. For target cell $i$ and source policy
polygons $s$, the standardized hat is

`hat_i = 1 + sum_s[(intersection_area_is / target_area_i) × (hat_s - 1)]`.

Thus uncovered target-cell area contributes the neutral value one. For
example, a `1.20` source hat covering 25% of a model cell yields `1.05` for that
cell. If policy polygons partition and fully cover a cell, this reduces to the
usual intersection-area-weighted mean. Overlapping policy polygons are rejected
because they would double-count target area. Cells with no intersection receive
one for every primitive.

The standardized result is saved as both `shocks/shocks.csv` for the model and
`shocks/shocks.gpkg` for spatial inspection. When map reporting is enabled, the
preparation stage creates three separate full-size maps:

- `imposed_fundamental_productivity.pdf` and `.png`;
- `imposed_fundamental_amenity.pdf` and `.png`;
- `imposed_structural_density.pdf` and `.png`.

Each map shows the percentage change in one primitive. Thin gray outlines identify the original policy polygons, and the
transport innovation is overlaid with a thin black line and white casing on
every panel. This allows the user to cross-check the areal attribution and
transport intervention before the economic model runs. A regulatory-wedge shock is not
accepted under the current one-rent model because no wedge primitive or
corresponding equilibrium equation has been introduced.
## Economic parameters

The `model` and `numerics` sections of `project_config.yaml` must document values, units, and sources where applicable. Together they cover:

- expenditure and production shares;
- commuting heterogeneity/elasticity;
- productivity and amenity spillover elasticities;
- construction technology, including the land share;
- fixed-point damping, tolerances, and iteration ceilings;
- normalizations and the selected city closure.

Substantive parameters and numerical controls should be visibly separated.

## Required validation report

Every run records:

- ID counts and set equality;
- missing, duplicate, nonpositive, and nonfinite values;
- employment balancing factor and before/after totals;
- geometry validity and coordinate reference system;
- matrix dimensions, order, unit, asymmetry, diagonal, and unreachable pairs;
- baseline/counterfactual matrix correlation and change distribution;
- the original YAML and resolved runtime-configuration snapshots with file hashes.

A failed contract check stops before Python inversion.
## Area-based GRID attribution

When `grid.mode` is `generate_from_source_layers`, `grid.cell_geometry` offers
three choices:

- `square`: create a regular square grid using `cell_size_km`;
- `hexagon`: create an equal-target-area regular hexagonal grid;
- `original`: retain every supplied source polygon as a model location and
  ignore `cell_size_km`.

For generated squares or hexagons, source polygons may differ from the target
cells. QUETRANSPORT computes their exact intersections in a projected metre
CRS. In `original` mode the same attribution code becomes an identity mapping
for non-overlapping source polygons, so the supplied geometry is used for
TTMATRIX centroids, Python model locations, shock aggregation, and all maps. Set
`original_id_variable` to retain a unique source identifier; leave it null to
generate sequential identifiers.

- Population and employment are **extensive**: a source value is multiplied by
  `intersection area / source polygon area` and contributions are summed. Their
  spatial mass is therefore preserved when the target grid covers the source.
- Wages, the common observed floor-space rent, and the developed variable are
  **intensive**: a target cell receives the intersection-area-
  weighted mean over source polygons.
- Boundary contacts with zero area receive zero weight.
- Allocation totals and ratios are written to
  `outputs/diagnostics/grid_validation.json`.

This method supports both very fine source grids and larger statistical zones
such as output areas. It assumes that polygons within the combined source
layers do not overlap each other in ways that double-count the same territory.
